# Launchers de WoW 3.3.5 y AzerothCore

Consulta de fuentes: 2026-10-07. El código se ha estudiado solo como referencia de arquitectura; este informe no propone copiar ni derivar código, interfaz ni recursos visuales.

## Alcance

Se revisaron proyectos públicos que declaran soporte para clientes 3.3.5/build 12340, distribuyen parches o se presentan como launchers para AzerothCore. La palabra «launcher» cubre aquí productos distintos: algunos solo configuran una instalación local y otros incluyen backend de distribución o herramientas de administración. Las fechas de actividad son la última fecha que las páginas consultadas permiten afirmar, no una garantía de mantenimiento futuro.

## Lectura para WarCrafted

- El launcher debe ser cliente de un manifest de confianza y mantener el estado del juego como condición de elegibilidad para jugar. Un botón deshabilitado en UI no basta: el proceso que lanza el juego debe consultar el resultado de validación actual.
- Separar los archivos obligatorios (versión y hash gobernados por WarCrafted) de los complementos voluntarios. Los launchers observados que solo activan/desactivan MPQ existentes no satisfacen reparación ni detección de corrupción.
- Si se publica un hash en GitHub Releases, autenticar también el manifest con una clave pública embebida o adoptar un diseño como TUF. Un atacante que pueda reemplazar el instalador y el archivo hash podría reemplazar ambos.
- No incrustar credenciales del usuario en Config.wtf ni guardarlas en JSON de texto claro. La lectura del código ajeno no justifica reutilizar su método.
- No se verificó que ninguno de los ejemplos mantenga compatibilidad completa con addons de cliente 3.3.5 privados. Las versiones de addon etiquetadas «Classic» por catálogos actuales no prueban compatibilidad con la API antigua 3.3.5.

## Incertidumbres

- Las páginas de GitHub y README cambian; se conserva la fecha de consulta de este informe. Las páginas consultadas de TMFAZE, Chill-Guy-Hub y SouthMemory no expusieron una fecha concreta de último commit. Se indica la laguna en vez de inferir actividad a partir de estrellas, forks o el estado actual del sitio.
- No se auditaron binarios, servidores de actualización ni código línea por línea de todos los proyectos. «Arquitectura observada» describe estructura y comportamiento documentados públicamente, no una auditoría de seguridad.
- Las licencias de código no conceden permiso para reutilizar assets, marcas, contenido de addons ni datos del cliente. Hay que confirmar los avisos de cada archivo antes de distribuir cualquier componente.
